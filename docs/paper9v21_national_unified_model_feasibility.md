# Paper9v2.1 全国统一模型可行性说明

## 结论

如果客户能够提供全国数据，理论上可以训练全国泛化模型，但不建议把 paper9v2.1 当前阶段的目标定义为“训练一个全国统一冻结模型，以后所有区县直接套用”。

更稳妥、也更符合当前工程状态的路线是：

```text
全国预训练模型 + 县域少量校准/微调 + 本地硬约束审计
```

原因是 paper9v2.1 当前本质上是县域级 `sample -> train -> plan -> audit` 流程。模型学习的是某个县域内部图斑置换动作的偏好，而不同县区之间的图斑数量、坡度结构、耕地和林地比例、连片格局、行政边界、永久基本农田、生态保护红线和工程可实施性约束都可能有显著差异。

中国区域差异很大。平原县、丘陵县、黄土高原县、喀斯特山区县、盆周山地县和东北黑土漫岗县的耕地调整空间不同。如果简单训练一个全国统一冻结模型，模型容易被样本量大的区域或某类地貌主导，在其他地貌区出现效果不稳定或解释困难。

## 三种技术路线

### 1. 当前 v2.1：县域专属训练

当前版本最适合的方式是每个县使用自己的 DLTB、权威坡度字段、行政区数据和业务约束，独立完成采样、训练、规划和审计。

这种方式的优点是稳定、可解释、审计口径清楚，适合当前自然资源部内网离线测试和客户验收。

### 2. 推荐下一步：全国预训练 + 县域微调

如果客户具备全国数据，最有价值的用途不是直接替代县域训练，而是用于训练一个全国预训练模型。这个模型可以学习较通用的动作偏好，例如：

- 耕地面积不减少。
- 耕地平均坡度下降。
- 耕地连片度提升。
- 尽量形成百亩方。
- 避免明显违反刚性管控边界。

到具体县区使用时，再用本地数据做少量采样和短周期训练，让模型适应本地坡度结构、地类组合、图斑尺度和政策约束。

这种路线既能利用全国数据，又能避免中国地形差异过大导致统一模型在部分地区失效。

### 3. 长期 v3：真正统一泛化模型

如果目标是实现“新县区免训练或极少训练即可使用”，需要把模型结构从县域专属模型升级为跨县泛化模型。

这通常需要把模型从依赖县域内部 block/action 编号，改为依赖图斑特征、邻接关系、地形地貌、行政上下文和约束条件来评分。可考虑的技术方向包括：

- 图斑特征编码器。
- 动作特征编码器。
- 图神经网络或邻接关系模型。
- Set/Transformer 类县域上下文编码器。
- 按地貌区或农业区划划分的 mixture-of-experts。
- 留省、留地貌区、留县验证机制。

这类能力更适合作为 paper9v3 的研发目标，不建议直接纳入 v2.1 当前离线交付范围。

## 建议给客户的沟通口径

如果客户问“有全国数据后，是否可以训练一个统一模型以后到处用”，建议回答：

> 如果有全国数据，理论上可以训练全国泛化模型，但 paper9v2.1 当前版本不是按这个目标设计的。v2.1 更适合县域级训练和审计。全国数据最有价值的用途，是训练一个全国预训练模型，形成通用的坡度降低、连片度提升、耕地面积不减少等动作偏好；到具体区县时再做少量本地校准。这样既能利用全国数据，又能避免中国地形差异过大导致一个冻结模型在某些区域失效。

## 推荐实施路径

建议分三步推进：

1. 先用 10-15 个代表性县区完成 paper9v2.1 验证，覆盖平原、丘陵、山地、黄土高原、喀斯特、盆周山地和东北黑土漫岗等典型场景。
2. 再扩展到 50-100 个分层抽样县区，训练全国预训练模型，并对比“从零训练”和“预训练后微调”的效果、耗时和审计通过率。
3. 最后做留省、留地貌区、留县验证，证明模型在新区域的泛化能力，再决定是否进入 paper9v3 的统一泛化模型研发。

## 当前阶段建议

当前自然资源部内网测试阶段，不建议一次性要求客户提供全国所有区县的全量图斑数据。更合理的是先要求客户提供全国县域汇总筛选表，再选择代表性县区提供全量 DLTB 和行政区数据。

这样可以同时满足三个目标：

- 控制数据交付和处理成本。
- 覆盖对算法最有挑战、最有业务价值的地貌场景。
- 为后续全国预训练和跨区县泛化模型留下清晰的数据基础。
