## 2. 总体结论

内网离线部署最终运行完成，核心产物完整，审计通过。与本机 Paper9v2.1 同数据结果相比，输入规模、准备阶段结构和硬约束口径一致，但最终优化方案不是逐图斑完全复现。

差异主要表现为：

- 内网结果和本机结果均满足耕地面积不减少约束。
- 内网结果的 `total_reward`、耕地面积增量和百亩方面积增量更高。
- 本机结果的坡度改善幅度略大。
- 两边最终耕地/林地状态总量一致，但具体被调整的图斑组合不同。
- 差异来源不在输入准备阶段，而在采样、训练和规划链路的非严格确定性上。

## 12. 业务解释风险与建议

1. 对客户说明时，不应说内网结果与本机结果逐图斑完全一致；应表述为同一数据、同一配置下均完成并满足硬约束，但由于采样/训练/规划链路非严格确定性，具体图斑组合存在差异。

2. 如果验收要求可复现实验，需要进一步固定所有随机源、线程数、BLAS/ONNX Runtime 行为，并尽量避免不同 CPU/运行时导致的浮点差异。

3. 对外汇报优化结果时，应使用 `OPT_DLBM/OPT_DLMC/CHG_FLAG`，不要把原始 `DLBM` 当作已覆盖结果。

4. 入库或叠加业务约束前，应处理或标注 238 个 invalid geometry。

5. 面积指标必须明确口径。当前 `mpc_summary` 使用几何面积口径，若客户按 `TBDLMJ` 或其他自然资源属性字段复核，数值会不同。

6. `511011214（区城镇）` 因无满足条件的可交换 block 被跳过，应在验收材料中作为边界情况说明。

7. 内网运行性能明显低于本机，尤其是 `sample` 和 `train`。若要在内网常态化运行，建议单独做 CPU 型号、线程数、容器资源限制和 BLAS/ONNX Runtime 性能诊断。
